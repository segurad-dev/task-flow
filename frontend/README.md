# Task Flow — Frontend Demo

Минималистичный SPA-интерфейс для демонстрации работы Task Flow API.

**Стек**: HTML + [Alpine.js](https://alpinejs.dev) (CDN) + [Tailwind CSS](https://tailwindcss.com) (CDN)  
Сборка не требуется — всё загружается через CDN.

---

## Запуск всего проекта с нуля

> Нужно два открытых терминала одновременно.

### Терминал 1 — Бэкенд (Docker)

```bash
# В корневой папке проекта (task_flow/)
docker-compose up --build
```

Дождитесь строк вида:
```
app       | INFO:     Application startup complete.
```

API станет доступен на **http://localhost:8000**  
Swagger UI: **http://localhost:8000/docs**

> При повторном запуске (без изменений кода): `docker-compose up` — без `--build`.

---

### Терминал 2 — Фронтенд (Python HTTP-сервер)

Откройте **новое** окно терминала. Перейдите в папку `frontend/`:

```bash
# Из корня проекта
cd frontend
python -m http.server 3000
```

Откройте **http://localhost:3000** в браузере.

> **Почему нельзя просто открыть `index.html` двойным кликом?**  
> Браузер блокирует загрузку внешних JS-файлов (`api.js`, `app.js`) по протоколу `file://`.  
> Локальный HTTP-сервер обходит это ограничение.

---

### Проверка работоспособности

1. Откройте http://localhost:3000 — должна появиться форма входа
2. Зарегистрируйтесь (кнопка «Регистрация»)
3. Войдите с теми же данными
4. Создайте проект через кнопку `+` в боковой панели
5. Добавьте задачи кнопкой `+ Задача`
6. Измените статус задачи через выпадающий список в строке задачи
7. Статистика в сайдбаре должна обновиться

## Что умеет интерфейс

| Функция | Описание |
|---|---|
| Регистрация / Вход | JWT-токен сохраняется в `localStorage` — сессия переживает перезагрузку |
| Проекты | Список, создание, переключение (автовыбор первого при загрузке) |
| Задачи | Список по проекту, фильтр по статусу, создание, смена статуса, удаление |
| Аналитика | Прогресс-бар выполнения, счётчики по статусам, среднее время завершения |
| Обработка ошибок | Toast-уведомление при ошибках API; авто-выход при истёкшей сессии (HTTP 401) |

## Структура файлов

```
frontend/
├── index.html   # SPA-оболочка: разметка, Alpine-директивы, CDN-скрипты
├── config.js    # API_BASE_URL — единственное место для смены адреса бэкенда
├── api.js       # Все fetch-запросы к бэкенду, единый обработчик ошибок
└── app.js       # Alpine-компоненты: authApp() и dashboardApp()
```

---

## Конфигурация

По умолчанию фронт обращается к `http://localhost:8000`.  
Чтобы указать другой адрес бэкенда, отредактируйте [config.js](config.js):

```js
const API_BASE_URL = "https://your-backend.railway.app";
```

---

## Деплой на GitHub Pages

GitHub Pages поддерживает только статические файлы — бэкенд нужно деплоить отдельно
(например, на [Railway](https://railway.app) или [Render](https://render.com)).

После деплоя бэкенда:
1. Обновите `API_BASE_URL` в `config.js`
2. Добавьте домен GitHub Pages в `allow_origins` в `app/main.py`
3. Скопируйте содержимое `frontend/` в корень ветки `gh-pages`
